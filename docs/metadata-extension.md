# 元数据扩展契约草案

状态：当前仅实现可独立 serde JSON 序列化的数据契约和普通同步 Rust trait；不实现插件加载或运行时，也不承诺第三方 ABI。

## 职责与数据流

```text
界面 → 刮削协调 → MetadataProvider → 候选列表/详情
                                         ↓
                                 用户确认 → 核心合并和保存
```

提供者识别媒体并返回来源数据；核心拥有 NAS 鉴权、用户覆盖、字段合并和持久化。JAV 是可选提供者的用途，不影响普通片库和播放。

## 最小契约

| 对象 | 约定 |
|---|---|
| `ProviderInfo` | 稳定提供者 ID、提供者版本、独立的契约版本、声明能力和命名空间扩展 |
| `ScrapeRequest` | 仅包含文件基名、用户输入编号、可选标题和语言；不含 NAS token、完整文件路径或播放地址 |
| `MetadataCandidate` | 提供者 ID、来源 ID、候选标题、年份/日期、人物、图片引用和命名空间扩展 |
| `MetadataDetails` | 候选来源、核心元数据、来源引用、图片引用和命名空间扩展 |
| `MetadataProvider` | 同步搜索候选、获取详情；使用取消令牌和请求 ID，区分无匹配、网络失败、认证要求、解析失败及取消 |

输入输出选择可序列化的数据类型；内部调用仍是普通 Rust 调用。契约版本、应用版本和提供者版本分开，首版不预造多版本协商机制。已知可选字段缺失和未知顶层字段可容错；扩展字段使用 `namespace -> JSON object`，未知命名空间保留。取消后不再应用旧请求结果，提供者错误不阻塞片库和播放。

候选和详情使用独立的 metadata 领域模型，不复用 NAS `Collection`/`Episode`。图片只返回引用，不在契约对象中携带图片或媒体内容。

## 元数据与保存

候选和详情携带来源 ID，以便再次查询及解释字段来源。作品编号、发行商等 JAV 字段放在提供者命名空间扩展中；只有证明是跨来源的稳定概念，才提升为核心字段。提供者不能自行覆盖用户修改或写 NAS。

图片以引用返回，由宿主按权限和缓存策略获取；不把大图片或媒体文件塞入通用结果对象。来源需要的密钥与 NAS 会话分开管理。

## 能力与未来运行方式

可以先声明网络域名访问等实际需要的能力；声明本身不等于权限执行。未来加载第三方代码时再选择进程隔离或其他沙箱并实现授权，独立进程并不自动限制文件和网络权限。

暂不选 DLL ABI、脚本语言、Wasm 运行时、独立进程协议或插件分发方式；不安装插件所需的运行环境。保留数据边界，可在未来将相同调用映射到版本化消息协议。
