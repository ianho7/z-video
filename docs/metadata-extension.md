# 元数据扩展契约草案

状态：用户已要求提前预留插件设计；首版不实现插件加载或运行时。以下命名是实现起点，最终 Rust 签名和字段类型随第一个真实提供者收敛，不承诺第三方 ABI。

## 职责与数据流

```text
界面 → 刮削协调 → MetadataProvider → 候选列表/详情
                                         ↓
                                 用户确认 → 核心合并和保存
```

提供者识别媒体并返回来源数据；核心拥有 NAS 鉴权、用户覆盖、字段合并和持久化。JAV 是可选提供者的用途，不影响普通片库和播放。

## 最小契约

| 对象 | 约定 |
|---|---|
| `ProviderInfo` | 稳定提供者 ID、版本、支持的契约版本及声明能力 |
| `ScrapeRequest` | 文件基名或用户输入编号、可选标题和语言；默认不含 NAS token、完整文件路径及播放地址 |
| `MetadataCandidate` | 提供者 ID、来源 ID、候选标题、年份/日期、人物和图片引用；来源不明的字段保持缺失 |
| `MetadataDetails` | 选择候选后的完整元数据、来源引用及有命名空间的可选扩展字段 |
| `MetadataProvider` | 搜索候选、获取详情；支持取消，区分无匹配、网络失败、来源要求认证及解析失败 |

输入输出选择可序列化的数据类型；内部首次调用仍是普通 Rust 调用。契约版本与应用版本分开，首版不预造多版本协商机制。取消后不再应用旧结果，提供者错误不阻塞片库和播放。

## 元数据与保存

候选和详情携带来源 ID，以便再次查询及解释字段来源。作品编号、发行商等 JAV 字段放在提供者命名空间扩展中；只有证明是跨来源的稳定概念，才提升为核心字段。提供者不能自行覆盖用户修改或写 NAS。

图片以引用返回，由宿主按权限和缓存策略获取；不把大图片或媒体文件塞入通用结果对象。来源需要的密钥与 NAS 会话分开管理。

## 能力与未来运行方式

可以先声明网络域名访问等实际需要的能力；声明本身不等于权限执行。未来加载第三方代码时再选择进程隔离或其他沙箱并实现授权，独立进程并不自动限制文件和网络权限。

暂不选 DLL ABI、脚本语言、Wasm 运行时、独立进程协议或插件分发方式；不安装插件所需的运行环境。保留数据边界，可在未来将相同调用映射到版本化消息协议。
