## Problem Statement

已确认的 HTML 浏览流程没有完整映射到原生应用。搜索提交目前只写状态文本，不产生结果；筛选、排序、继续观看横向模块缺失；返回只有分类/列表模型保留，搜索、滚动和焦点恢复尚未完整验证。当前 Collection 列表仅取一页50条，不能把这一页的本地筛选伪装为全库搜索。用户看到“可输入”的控件却无法完成选片路径。

## Solution

让搜索、筛选、排序、继续观看、详情与返回形成可操作闭环。每项能力明确数据范围和协议证据；未知能力先调查已有逆向记录，再做有限验证。无能力时呈现明确不可用/范围说明，不显示假成功或静默空列表。

## User Stories

1. As a 片库用户, I want 搜索输入实际改变结果, so that 可以找到 Collection。
2. As a 片库用户, I want 知道搜索覆盖当前页还是全库, so that 不会漏片而不自知。
3. As a 片库用户, I want 清空搜索恢复浏览, so that 无需重启页面。
4. As a 片库用户, I want 筛选和排序作用于声明的数据范围, so that 结果可解释。
5. As a 用户, I want 快速改词时只显示最新查询结果, so that 慢响应不会覆盖新结果。
6. As a 用户, I want 加载、无结果和请求失败可区分, so that 知道是否需要重试。
7. As a 用户, I want 继续观看使用紧凑横向16:9缩略图和进度, so that 首屏不会被竖卡和留白占满。
8. As a 用户, I want 继续观看基于真实观看历史, so that 不会续播错误 Episode。
9. As a 用户, I want 点击继续观看进入对应详情与选集, so that 和已确认原型路径一致。
10. As a 用户, I want 有效续播入口恢复正确位置, so that 不从头播放或关联到其他影片。
11. As a 用户, I want 返回保留查询、筛选、排序、滚动和焦点, so that 能接着浏览。
12. As a 用户, I want 长时间浏览不反复重新下载封面, so that 操作稳定。
13. As a 键盘用户, I want Ctrl/Cmd+K聚焦搜索且Esc从详情返回, so that 主要路径高效。
14. As a 用户, I want 不支持的功能明确说明, so that 不会被占位按钮误导。

## Implementation Decisions

- 复用现有 Rust 应用协调、NAS client、Collection/Episode/Playback session、图片缓存和请求代次机制，Slint只展示状态并投递动作。
- 先核对既有协议证据：搜索、筛选/排序、分页、收藏及观看历史的端点、参数、响应与静态/运行时覆盖。必要的只读验证脱敏记录；不重跑已有效的登录/播放证据，不擅自执行NAS写操作。
- 当前仅加载50条，若先做已加载集合内查询，应明确标注范围。全库搜索和总数排序须使用有证据的服务能力或实际完整的数据范围，不能靠一页数据冒充。
- 查询输入及时反馈，后台请求防抖、支持Enter立即提交；旧结果失效。返回保存来源上下文，不为返回重拉整片库。
- 继续观看使用有证据的历史来源关联Collection与Episode；有真实历史时显示横向条目，没有历史时合理隐藏/空态，历史请求失败可重试。不得逐条请求全库详情来凑首屏，不伪造进度。
- 展示进度百分比须有有效时长；仅有位置时显示已看时间。续播复用现有Playback session机制，区分“播放请求已发出”与真实开始/保存成功。
- 原型中收藏等入口只有在数据契约确认后启用；未验证的元数据或操作不得静默实现为假集合。
- 不引入独立本地索引、数据库或新后台服务。性能先记录任务取消、查询时延与界面响应，按实际瓶颈改进。

## Testing Decisions

- 用户确认：主要行为证明扩展现有应用协调器/详情导航测试入口，以脱敏NAS替身提供查询数据、延迟和错误，驱动与产品相同的动作。期望来自本spec和独立fixture，不用查询实现生成期望值。
- 覆盖快慢查询乱序、清空、筛选排序范围、空结果/协议失败区分，以及搜索后打开详情再返回保留上下文。现有详情测试只断言分类、条目数和选集，无法覆盖查询/滚动/焦点，因此扩展该责任边界而非重复建多层同场景测试。
- 继续观看用不同Episode、缺失时长、缺失历史的fixture检查正确关联；不在该用例重新证明NAS真实持久化。真实历史/搜索协议有变更时才在NAS边界保留一份独立脱敏契约证据。
- 主窗口实际操作和截图证明横向模块、加载反馈、焦点/滚动恢复及主路径。用非敏感海报和片名；不上传用户截图。
- 编译检查为前置条件，模拟进度不等于真实播放或NAS保存。复用仍有效的已有播放验收证据。

## Out of Scope

独立媒体服务器、刮削系统、管理写入、删除/回收站、远程NAS、多NAS框架、播放器引擎更换、全局自动化测试平台和未验证性能百分比承诺。

## Further Notes

本 issue 接续网格与视觉外壳修复；交互可独立在协调器边界实施，但最终验收需合并后的原生窗口。能力调查若发现阻塞，记录具体端点/返回形状/覆盖范围和可行替代，不把缺失能力写成已完成。

已确认首期范围及Rust + Slint架构继续有效。HTML为设计基准，不是最终UI；不新增WebView。
