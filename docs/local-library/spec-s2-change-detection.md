# S2 Spec：变更感知

Status: 已批准（2026-11-15），Ticket 23a / 23b / 24a / 24b。
词汇遵循 `GLOSSARY.md`：Source、Media file、Scan run、Degraded source、Marker。

## Problem Statement

用户在资源管理器里改了 NFO、加了或删了视频，应用完全不知道，必须手动点"重新扫描"；而现有扫描是整棵遍历，20k 文件约 30 秒，频繁手动刷新既慢又打断浏览。用户真正想要的是：改完切回应用就能看到正确结果，最好连切都不用切。

## Solution

把"发现问题"和"扫描问题"分开：

1. **增量扫描**：只重扫指定的目录，返回精确的四类计数（imported / updated / unchanged / removed）。
2. **变化发现**：三条互补的路径产生"脏目录"——目录 mtime 校验（最稳）、本地盘监听（最快）、网络盘轮询（兜底）。
3. 三者共用同一个防抖队列与单飞守卫，自动刷新静默进行，不打断详情与播放。

## User Stories

1. 作为用户，我改完 NFO 切回应用，条目自动更新，不需要点扫描。
2. 作为用户，我新增一个视频文件后回到片库，能看到它。
3. 作为用户，我删除一个视频后，条目变成不可用，而不是继续显示可播。
4. 作为用户，自动刷新只处理变化的目录，不整库重扫，所以等待时间很短。
5. 作为用户，计数区分新增/更新/未变/移除，不会看到"更新了 20000 项"这种噪音。
6. 作为用户，我正在详情或播放时，刷新延后而不是打断我。
7. 作为用户，本地盘上的变化几秒内反映，不用切窗口。
8. 作为用户，网络盘上的变化在合理周期内反映，允许比本地慢。
9. 作为用户，监听不可用时不弹错误、不影响手动扫描。
10. 作为用户，自动刷新与手动扫描不会同时进行而互相破坏。
11. 作为用户，只改 NFO（视频没变）时，播放进度与观看历史不被清掉。
12. 作为用户，换片（指纹变化）时仍按既有语义处理：旧行不可用、进度不继承。

## Implementation Decisions

- 新增"按目录重扫"能力：输入来源与相对目录集合，只遍历这些目录，复用现有的文件发现、NFO 解析与 upsert 逻辑。
- 计数由"库内已有行"与"本次见到"比对得出，分四类；NFO-only 变化与视频指纹变化分开统计。
- 缺失判定收紧到目录级：只有该目录被完整扫描，才把目录内未见的文件标为不可用。
- 目录清单从库内已有数据推导（每个 Media file 的父目录），用于 mtime 粗筛；不额外建表。
- 触发点：窗口重新获得焦点、从详情或播放器返回片库。不做常驻定时刷新。
- 本地盘使用递归文件系统监听，事件只用于收集脏目录；1.5 秒防抖、合并去重、忽略临时文件与系统垃圾文件。
- 网络盘判定为 UNC 或映射网络驱动器；使用低频目录 mtime 轮询（默认 5 分钟，仅前台），并明确不承诺秒级。
- 自动刷新与手动扫描共用单飞守卫；扫描期间到达的脏目录排队，不丢弃。
- 刷新结果静默推送到片库；用户位于详情或播放器时只更新数据，不抢焦点、不切视图。
- 不新增 schema；扫描记录沿用既有 Scan run。

## Testing Decisions

好的测试验证外部可观察行为：给定目录内容，断言扫描计数与行状态；不改内部实现细节、不断言私有函数。

- **Owner 冒烟**（`test:local-library`）：按目录重扫、四类计数、NFO-only 与指纹变化区分、目录级缺失判定、非法路径拒绝。这是主缝。
- **变化源注入**（测试侧新缝）：把"变化事件"抽象成可注入来源，用假事件验证防抖、合并、排队与单飞；**不**直接依赖真实 `fs.watch`（不可靠、易 flake）。
- **Window 冒烟**（`test:window`）：聚焦触发、详情/播放期间延后、刷新后列表与滚动不被重置。
- 真实网络盘监听行为不写成自动断言，列为真机验收。

## Out of Scope

- 网络盘的实时逐文件监听。
- 云端目录、自动重命名、自动刮削或写回 NFO。
- 文件内容级校验（例如只改文件内容但 size/mtime 不变的情况）。
- 全库 mtime 快照与 NTFS USN 日志方案。

## Further Notes

- 三条发现路径的优先级：监听（最快）> mtime 校验（最稳）> 轮询（兜底）。任一不可用时其余仍能工作。
- SMB 的目录 mtime 与事件都不可靠，这是"网络盘只承诺最终一致"的原因；mtime 校验必须在监听之外保留。
- 文件正在播放时被删除：当前播放不受影响，下一次扫描把该行标不可用，不主动中断播放。
- 先做增量扫描与计数，再接触发与监听——前者不依赖任何 OS 监听，就能拿到大部分收益。
