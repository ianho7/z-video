# 审计 blocker 的自动化验收

ID: 20b-automated-acceptance
Blocked by: 20
Status: ready-for-agent

## What to build

把 Ticket 20 中尚未自动化的六条交互变成可重复执行的窗口冒烟，使验证不再依赖人工点击。用户只在最终真实媒体验收阶段参与。

覆盖：

1. F-01：数据库路径不可用时，主进程仍创建窗口并显示错误卡（不是无窗口退出）。
2. F-04：错误卡"重试"真实重试；恢复数据后不重启即可回到可用状态。
3. F-05：搜索失败显示可重试错误态，且不出现"共 0 部作品"。
4. P-07：控制命令失败时出现可见提示，进度滑块回弹。
5. B-06：移除来源忙碌期间按 Esc 不关闭对话框，失败信息落在可见对话框里。
6. CL-08：检查模式播放结束后"重新播放"从头重开同一候选。

## 约束

- 只改 `tests/**`、`scripts/**`、`package.json`（新增脚本）。
- **不改生产行为**。优先用环境隔离实现，而不是给 `src/` 加测试专用开关：例如为子进程设置临时 `APPDATA` 使 `userData` 落到临时目录，再动态 import 生产 main。
- 所有冒烟必须使用一次性临时 profile，结束后清理；**不得触碰** `%APPDATA%\z-video-electron` 下的真实数据。
- 每条检查要有"失败先行"证据（能复现旧行为即复现；不能复现的写清原因）。
- 不新增依赖。

## Acceptance criteria

- [ ] 新增脚本可在无人值守下运行，退出码表达结果。
- [ ] F-01/F-04 通过：非法 DB 路径下窗口出现且显示错误卡；恢复路径后重试成功。
- [ ] F-05 通过：失败态有重试入口，计数文案不出现"共 0 部作品"。
- [ ] P-07 通过：命令失败有可见提示，滑块回弹到服务端位置。
- [ ] B-06 通过：忙时 Esc 不关闭，提示可见。
- [ ] CL-08 通过：`ended` 后重播从头开始，且仍属于同一候选。
- [ ] 运行前后真实用户数据目录内容不变（可用 mtime/文件列表断言或仅靠隔离路径保证）。
- [ ] 全部跑完无残留临时目录、无残留窗口。

## Verification

新增脚本 + 现有 `npm run typecheck` / `npm test`。
窗口类命令需要 GUI 权限，但由 agent 执行，不要求用户操作。
