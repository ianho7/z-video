# Local library contracts

Status: Ticket 01 foundation contract, accepted 2026-10-31. Owners: `src/main/local-library-worker.ts`, `src/main/local-library-database.ts`, `src/main/local-library-ipc.ts`, and `src/shared/local-library-contracts.ts`.

## Schema v1

The utility process creates these tables in the database under application `userData/local-library/library.sqlite`:

| Table | Foundation fields | Next owner |
|---|---|---|
| `sources` | `source_id`, `root_path` (main/worker only), `label`, `available`, timestamps | 02 scan |
| `collections` | `collection_id`, `title`, `kind`, optional year/plot/genre/rating, timestamps | 02 metadata |
| `media_files` | `media_id`, `collection_id`, `source_id`, `relative_path` (main/worker only), `size_bytes`, `modified_at_ms`, `available`, timestamps | 02 scan / 03 playback |
| `artwork` | `artwork_id`, `collection_id`, `kind`, source fingerprint/cache key | 02 metadata |
| `playback_state` | `media_id`, position/duration, audio/subtitle track IDs, watched, updated time | 03 playback |
| `scan_runs` | source, generation, completion, error, start/completion times | 02 scan |

`PRAGMA user_version` is `1`. The worker uses prepared statements and enables foreign keys. The first import creates one movie collection and one media file; NFO/artwork mapping is deliberately deferred to ticket 02.

## Public IPC

Channels are defined in `src/shared/ipc-channels.ts` and exposed through `window.zVideo.localLibrary`:

- `local-library:state` → `LocalLibraryState`; reports schema version, SQLite availability, safe source labels/counts, and an actionable storage error.
- `local-library:choose-folder` → opens a main-owned directory picker and imports the first supported video; returns `cancelled`, `empty`, or `imported` with safe item/state.
- `local-library:open-video` → opens a main-owned video picker and imports the selected file under its parent root.
- `local-library:list` → validates bounded page/query input and returns `LocalLibraryPage` with renderer-safe items.
- `local-library:get` → validates opaque `mediaId` and returns one renderer-safe item; missing media is not a path error.

Renderer-visible `LocalMediaItem` fields are `mediaId`, `sourceId`, title, kind, size, modified time, and availability. Absolute paths, UNC paths, source-relative paths, database rows, credentials, NAS signs, and raw playback URIs are never part of the public DTO.

## Identity

`mediaId` matches `media_<UUID>` and is generated by the worker. An unchanged `(source root, relative path, size, modified time)` reuses the existing ID. A changed fingerprint marks the previous row unavailable and creates a new ID without inheriting playback state. Path resolution is main-only and enforces the selected root boundary.

## Handoff

Ticket 02 may add metadata columns/records only through the schema owner and must preserve the opaque-ID and path boundary. Ticket 03 may use the main-only resolve method and `playback_state`, but must not add a renderer path escape hatch or NAS progress write.
