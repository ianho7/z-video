# 体验流程审计（UX Flow Audit）

Status: 2026-11-14 立项，方法已定，操作清单为草案（待用户过一遍后进入走查）。
关联：`docs/local-library/state-machines.md`（代码侧状态载体）、`docs/research/feature-ideas-2026-11-14.md` §12（阶段划分 P0.5）。
边界：**只读审计**，不修改代码；修复在 P0（Ticket 15）之后单独排期。

## 1. 目的与方法

目标不是"找 UI 不好看的地方"，而是**沿用户路径验证状态流转是否完整、可恢复、无死路**。

四步：

1. **操作清单**：把 App 内所有可发起的操作列全（本文件 §3）。
2. **状态模型**：为每个操作标注它读写的状态（视图、片库、播放、扫描、整理、来源）。
3. **路径矩阵**：每个操作至少走 主路径 / 分支 / 异常 三类，并记录恢复方式（本文件 §4 模板）。
4. **发现与分组**：按 §5 的标准判定问题，聚成修复主题，产出 Ticket。

## 4. 路径矩阵模板

每个操作按此表走查：

| 项 | 记录 |
|---|---|
| 操作 ID | C5 |
| 前置状态 | library/ready，有 ≥2 页 |
| 主路径 | 点排序 → 列表重排 → 偏好保存 |
| 分支 | 排序时正在扫描；排序时无内容 |
| 异常 | IPC 失败；偏好保存失败 |
| 恢复 | 失败后是否保留原排序、是否提示 |
| 证据 | 代码位置 / 截图 / 运行记录 |
| 结论 | 通过 / 问题（严重度） |

## 5. 问题判定标准

1. **死路**：进入某状态后没有任何返回或退出路径。
2. **状态残留**：切换后旧视图/旧字段仍可见或仍生效。
3. **静默失败**：操作失败但用户看不到任何反馈。
4. **误导文案**：显示的状态与真实状态不符（例如把 degraded 说成离线）。
5. **不可恢复**：错误发生后只能重启应用。
6. **缺态**：只有加载态与成功态，没有空态或错误态（或反之）。
7. **焦点/滚动丢失**：返回后回不到原来的位置。
8. **并发破损**：快速点击/切换导致重复提交、双弹窗、状态错位。
