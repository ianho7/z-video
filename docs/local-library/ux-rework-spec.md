# 本地片库 UX 重做：作品优先、无需说明书

Status: ready-for-agent  
Triage: ready-for-agent  
Date: 2026-11-08  
Scope: 本地片库的首次使用、浏览、搜索、详情、播放连续性、文件夹管理、空/错/离线状态，以及原生控件、动效、字体内嵌、原生手感与无障碍收口。  
Design reference: `designs/ux-rework-2026-11-08-motion/`（Kimi K3.1 Pro 的 13 画板设计 + 动效/原生手感增补，14 画板 / 42 状态；v1 与 v2 保留作对照）。

## Problem Statement

用户只想把自己电脑上的电影和剧集看完。他不懂“来源、索引、媒体条目、NFO、S01E01”，也不应该需要懂。当前本地片库虽然能导入和播放，但整个产品是按“文件”而不是按“作品”组织的：

- 剧集被拆成一张张单集卡片，卡片通常没有剧名；8000 个文件就是 8000 张卡，“剧集”和“电视剧”两个筛选几乎返回同一批内容。
- 首次添加文件夹后没有可见的进度和取消；欢迎卡消失，首页只剩一行字；默认 1040 窗口连扫描状态胶囊都被隐藏。
- 关闭播放器一定退出详情，想看下一集必须重新找剧；长片名在详情页被截断；搜索框在详情页仍可输入，却只会在背后悄悄改变片库。
- 空片库、存储错误、来源离线都没有真正的下一步；删除来源会删除观看进度，但确认框只说“不删除源文件”。
- 8000 项、每页 24 个、没有跳页，翻完要 334 页；换页、筛选、进详情都不回到顶部。
- 音量滑杆、音轨/字幕下拉、播放结束按钮、滚动条、搜索清除仍是未统一的原生控件。

这不是“视觉再打磨”的问题，而是用户无法稳定完成“添加 → 找到 → 播放 → 回到原处 → 管理”的主流程。目标是让第一次使用的人不需要说明书，也能完成这五步。

## Solution

把本地片库从“文件列表”改成“作品优先”的片库：

- 默认一张卡代表一部作品（Collection）：电影一卡一片，剧集一剧一卡；卡片显示剧名、年份、集数、已看进度和继续观看的集数。需要看文件时，切到“单集”视图。
- 顶部导航固定为“首页 / 片库 / 文件夹”；筛选固定为“全部 / 电影 / 剧集 / 单集 / 未分类”。“剧集”只指 show，“单集”只指 episode。
- 首次扫描在首页和顶栏都可见、可取消；欢迎卡保留到第一条内容出现；扫描完成给出不会立刻消失的摘要。
- 播放器关闭回到打开它的详情/首页，并恢复选集和滚动位置；片尾提示显示下一集名称。
- 空、错、离线状态都给下一步按钮；删除文件夹明确说明会删除观看进度，并使用 destructive 确认。
- 统一控件语言：自绘滑杆、应用内菜单、深色滚动条、SVG 图标、可关闭的设置面板；字体、动效和原生手感按第 7/8 节。
- 术语全部换成用户词：文件夹、扫描、加入片库、第 1 季 第 1 集、上次看到。

## User Stories

1. 作为第一次使用的用户，我希望欢迎页说明“只读取文件夹，不移动也不上传文件”，以便我敢选择自己的媒体目录。
2. 作为第一次使用的用户，我希望欢迎卡一直保留到第一条内容出现，以便我任何时候都有“添加文件夹”入口。
3. 作为第一次使用的用户，我希望在首页看到正在扫描的文件夹、已扫描数量和已加入数量，以便我知道它没有卡死。
4. 作为第一次使用的用户，我希望在首页直接取消扫描，以便选错文件夹时不用等它跑完。
5. 作为第一次使用的用户，我希望扫描结束看到“新增/更新/警告”的摘要，而且摘要不会马上被总数量覆盖，以便我知道发生了什么。
6. 作为第一次使用的用户，我希望空首页同时有“添加文件夹”和“添加单个视频”，以便我不会被困住。
7. 作为电影观众，我希望点“添加单个视频”后进入它的详情并看到播放按钮，以便我确认加对了并马上播放。
8. 作为电影观众，我希望知道单个视频导入也会把所在文件夹登记为片库文件夹，以便以后重新扫描不会惊讶。
9. 作为片库主人，我希望“添加文件夹”和“重新扫描文件夹”是两个明确不同的动作，以便我不会重复添加同一个文件夹。
10. 作为片库主人，我希望文件夹卡显示盘符或上级线索，以便两个都叫 Movies 的文件夹可以区分。
11. 作为片库主人，我希望可以只重扫一个文件夹，也可以重扫全部文件夹，以便外部新增的文件能出现。
12. 作为片库主人，我希望外部文件变化在刷新后可见，以便片库不会长期过期。
13. 作为剧集观众，我希望一张剧卡显示剧名、年份、总集数、已看集数和“继续第 2 季 第 3 集”，以便我能直接选剧。
14. 作为剧集观众，我希望“剧集”只表示 show，“单集”只表示 episode，以便两个筛选不再混淆。
15. 作为剧集观众，我希望从剧卡一眼看到“继续哪一集”，打开详情后主按钮就是继续播放，以便少走弯路。
16. 作为剧集观众，我希望剧集详情有季度切换和单集列表，以便我能选任意一集。
17. 作为剧集观众，我希望每一集都有自己的已看/进度标记，而不只是当前选中的那一集，以便我知道看到哪里。
18. 作为剧集观众，我希望片尾提示显示下一集名称，以便我决定要不要继续。
19. 作为剧集观众，我希望关闭播放器后回到这部剧的详情，以便接着选下一集。
20. 作为电影观众，我希望电影一卡一片，以便片库不被文件塞满。
21. 作为电影观众，我希望详情页完整显示长片名，以便我能确认看的是哪一部。
22. 作为电影观众，我希望“继续播放 / 从头播放 / 重新播放”语义明确且互不误触，以便不会误清进度。
23. 作为观众，我希望片尾有重播、下一集、返回详情，按钮有明确主次，以便我知道哪个能点。
24. 作为观众，我希望音量滑杆和进度滑杆看起来、用起来是一套，以便我不用猜。
25. 作为观众，我希望播放设置面板有标题、分组、关闭按钮，支持 Esc 和点外关闭，以便我改音轨/字幕时不会卡住。
26. 作为观众，我希望音轨、字幕、倍速的触发器和应用其它控件一致，以便不再看到裸露的系统下拉。
27. 作为观众，我希望播放失败时在播放器里看到原因和“重试/返回”，以便我知道是文件问题还是等待。
28. 作为键盘用户，我希望打开详情时焦点到详情标题，返回时焦点回原卡片，以便我不会丢失位置。
29. 作为键盘用户，我希望 Esc 能关闭设置/菜单，焦点环始终可见，以便我能不用鼠标操作。
30. 作为读屏用户，我希望筛选/翻页时只播报结果数量，而不是整页卡片，以便我能听清变化。
31. 作为读屏用户，我希望扫描进度和片尾倒计时以合理频率播报，以便我知道发生了什么。
32. 作为低视力用户，我希望应用尊重 Windows 高对比度和系统显示缩放，并提供 100/125/150% 界面缩放，以便我能看清界面。
33. 作为桌面用户，我希望有一个可见的“帮助/快捷键/关于”入口，以便我找不到命令时不用猜。
34. 作为小屏用户，我希望 1040×720 和 900×640 下所有主要按钮、筛选、详情都不被裁切，以便我能正常使用。
35. 作为用户，我希望搜索是显式的“搜索结果”视图，有标题、数量和返回路径，以便它不会悄悄改掉当前片库。
36. 作为用户，我希望搜索剧名或单集名都能找到那部剧，并标出匹配的单集，以便我能找到正确的剧。
37. 作为用户，我希望清除搜索后回到搜索前的页面，以便不丢失上下文。
38. 作为用户，我希望搜索、筛选、排序的保留/重置规则可预测，以便我知道当前看到的是什么。
39. 作为用户，我希望“全部”显示作品数而不是文件数，以便 8000 集不会看起来像 8000 部片。
40. 作为高级用户，我希望仍能切到“单集”看文件级列表，以便我需要按文件浏览时不被限制。
41. 作为用户，我希望分页有首页/末页/跳页和“第 X / Y 页”，顶栏保持可见，以便大库可以导航。
42. 作为用户，我希望换页/筛选/搜索回到顶部，返回时恢复原滚动位置，以便不会落在页面中间。
43. 作为用户，我希望每个空状态都告诉我下一步并给出按钮，以便我不会卡在空白页。
44. 作为用户，我希望存储错误用普通话解释，并提供重试、重启、复制诊断信息，以便我能采取行动。
45. 作为用户，我希望离线条目说明为什么不能播、怎么恢复，以便我不会以为应用坏了。
46. 作为用户，我希望移除文件夹时明确“会删除观看进度，不删除源文件”，并用红色 destructive 确认，以便我不误删数据。
47. 作为用户，我希望移除失败时错误留在对话框里可以重试，以便我不用重新走一遍。
48. 作为用户，我希望滚动条、下拉、滑杆、按钮都是这套深色设计的一部分，以便应用看起来是完成的。
49. 作为用户，我希望界面使用“文件夹/扫描/单集/上次看到”而不是“来源/索引/NFO/S01E01/媒体条目”，以便我不需要说明书。
50. 作为维护者，我希望作品列表只通过一个受界查询返回安全 DTO，以便 renderer 不加载整库、不接触私有路径。
51. 作为维护者，我希望新行为复用现有 app smoke 和数据库 facade 测试，以便不新增测试框架。
52. 作为维护者，我希望本 spec 除 B0 的 `premiered_at` 外不扩散 schema 变更，以便这次能安全交付。
53. 作为用户，我希望误点开 1 秒的视频不要进入“继续观看”，以便片架反映真正的观看。
54. 作为用户，我希望“继续观看”的计数和能浏览到的卡片一致，以便不会看到“30 项”却只翻到 12 张。
55. 作为 Windows 用户，我希望重复双击只聚焦已有窗口，以便不会同时跑两个扫描器。
56. 作为用户，我希望切换顶部导航时旧搜索词不会偷偷生效，以便我看到的列表和选中的 tab 一致。
57. 作为用户，我希望排序里能有“最近发布”，按 NFO 的首播日期排序，以便新片和老片按发布时间排列。
58. 作为用户，我希望“最近发布”用 NFO 的真实年月日排序；没有日期的条目只显示“日期未知”并排在最后，而不是拿年份冒充日期。
59. 作为观众，我希望动效只解释“我刚做了什么、接下来会发生什么”，不做循环装饰，以便界面像影院而不是手机应用。
60. 作为观众，我希望播放路径的动效不超过 200ms 且可跳过，以便不会为了转场耽误看片。
61. 作为观众，我希望扫描中只有一个表达活动的循环指示，其他区域保持静止，以便长时间使用不分散注意力。
62. 作为低视力/晕动敏感用户，我希望动效默认跟随系统“减少动画”，并能手动切到更弱或关闭，以便不被迫接受位移和缩放。
63. 作为键盘用户，我希望焦点环永不动画、只在键盘操作时出现，以便定位清楚且点击控件不出现矩形边框。
64. 作为用户，我希望正文和标题不能被鼠标拖选，只有输入框可选中文字，以便界面像原生应用。
65. 作为用户，我希望右键菜单、图片拖拽和整块选中默认不出现，以便没有“网页套壳”的感觉。
66. 作为用户，我希望搜索框输入时没有内部矩形边框，焦点只由外层胶囊表达，以便视觉统一。
67. 作为用户，我希望全站字体与真实应用一致（Nunito 优先、内嵌字体），不要有的地方是雅黑、有的地方是 Nunito。
68. 作为用户，我希望菜单、设置面板和播放器里的选择都用同一套应用内控件，不再出现系统浅色弹层。

## Implementation Decisions

### 1. 产品词汇与信息架构

- 用户可见词汇固定为：作品（Collection）、电影、剧集（show）、单集（episode）、文件夹（Source）、扫描、加入片库、上次看到。
- 顶部导航改为三个目的页：首页 / 片库 / 文件夹。电影/剧集/单集只作为片库筛选，不再同时出现在顶部导航，避免两个同名控件同时高亮。当前项始终高亮；详情沿用进入时页面的导航项。
- 顶部“+”改为有文字的“添加”，菜单只保留“添加文件夹 / 添加单个视频”。去掉“扫描目录”；重扫只放在文件夹卡片。
- “片库”页的筛选为：全部 / 电影 / 剧集 / 单集 / 未分类。前四项中的“单集”切到文件级列表；其余切到作品级列表。
- 计数分成两种：作品视图显示“共 N 部作品”，单集视图显示“共 N 集”。文件夹卡同时显示“N 部作品 / M 集”。
- “最近更新 / 最近添加”改为“最近观看 / 最近加入”；排序另增“最近发布”（NFO 首播日期），规则在界面上可解释。
- 作品列表默认排序为“最近加入”；用户已保存的排序偏好优先于默认值。首页“最近加入”片架固定用加入时间。

### 2. 作品级数据与 IPC 契约

本轮需要一次很小的 schema 增量（B0）：给 `collections` 增加 `premiered_at`，让“最近发布”有真实日期可用；其余作品聚合仍不新增 schema。

- `LocalCollectionSummary`：collection ID、标题、kind（movie/show/unclassified）、年份、评分、`premieredDate`（NFO 首播日期，`YYYY-MM-DD`，缺失为 null）、总集数、已看集数、可用集数、代表 media ID（详情默认集）、封面 media ID（优先有 poster 的集，取不到则退回代表集）、续播信息（media ID、位置、时长、季/集号、单集标题）、搜索命中单集、加入/更新时间。
- `LocalCollectionPage`：items、totalCount、page、pageSize；计数是作品数。
- `LocalCollectionQuery`：page、pageSize、query、filter（all/movie/show/unclassified）、sourceId、sort（含 `released_desc`）。
- `LocalContinueWatchingItem` 增加 collectionTitle、collectionKind、seasonNumber、episodeNumber、episodeTitle，并改为每个 Collection 只保留最近一条进行中的 Episode。
- `LocalMediaDetail` 增加每集播放状态列表，供详情页给每一集画已看/进度，而不是只给当前集。
- `LocalSourceSummary` 增加 collectionCount 和 locationHint；itemCount 仍是文件数，locationHint 只给盘符或上一级文件夹名，不暴露完整路径。

接口行为：

- 新增一个“列出作品”的 IPC/preload 方法，挂在现有 local library 边界内；沿用现有分页、source、query 校验和错误映射。
- 作品列表由 local library worker 聚合：按 collection 统计集数、已看数、可用数、最近播放、最近加入；选择“代表 media ID”的顺序是：进行中的续播集 → 第一集未看 → 第一集。
- 作品卡整体打开详情；续播信息（第 2 季 第 3 集 · 12:04）只作文案，不把播放按钮嵌套进卡里；继续播放的主动作在详情页。
- 排序定义：`recent` 显示为“最近观看”，取该作品最近一次 playback 更新时间，没有播放则退回最近 media 更新时间；`added_desc` 显示为“最近加入”，取该作品最近 media 加入时间；`released_desc` 显示为“最近发布”，按 NFO 的 `premiered_at`（`YYYY-MM-DD`）降序，缺少日期的作品排在最后，再按 `year`、`added_desc` 决胜。
  - 数据来源：NFO 的 `<premiered>`（兼容 `<releasedate>`）解析出日期；解析器保留 `year`，新增 `premieredDate`，只接受合法 `YYYY-MM-DD`，非法/缺失为 null。`collections` 增加 `premiered_at TEXT` 持久化列；**不能用年份倒装日期**。
  - B0 migration：`collections.premiered_at` 为增量列，加 `collections_premiered_at` 索引，`user_version` 升到 2；旧数据 `premiered_at` 为 null，不猜测日期。A 模块随后使用 schema v3。
- 作品封面用封面 media ID 走现有 artwork 通道；没有海报时继续用生成封面，生成封面改为接受作品标题/kind/年份/集数，不再依赖单个文件标题。
- 详情继续使用现有“按 media ID 取详情”的接口：点击作品卡时传入代表 media ID，就能拿到整个 Collection 的剧集与续播状态。不新增详情接口。
- 搜索匹配作品标题或任一单集标题；只命中单集时，作品卡显示“匹配：第 2 季 第 3 集 · 集名”，不重复出现同一作品。
- “单集”视图继续用现有文件级列表接口，保留现有分页和搜索，避免破坏高级用户路径。
- 单个视频导入不改变现有“父文件夹成为 Source”的契约；只改文案和后续行为：选完打开该视频详情，主按钮即播放，并在文件夹卡上说明重新扫描会加入整个文件夹。播放器从详情打开时，关闭返回详情。
- “继续观看”每个 Collection 只保留最近一条；只有已播放至少 30 秒（片长不足 10 分钟时至少 3%）才进入；界面不再只取前 12 张，显示全部返回项（上限 50）并提供左右翻页，计数与卡片一致。
- 作品卡不显示文件大小；显示年份、集数、已看/总集数、离线状态；有 `premieredDate` 时可在详情/排序菜单中显示发布日期，缺失则显示“发布日期未知”，不伪造。单集视图才显示文件大小。
- “最近发布”排序选项在 B0 migration 后显示；没有 `premieredDate` 的条目仍可出现在“全部”列表中，只是排在已发布日期条目之后，并显示“发布日期未知”。
- 首页继续观看特写压缩到约 200px，首屏同时可见扫描卡和第一个片架；不再让 420px hero 独占首屏。
- B0 只新增 `collections.premiered_at`；不改其它表。contracts 文档、NFO fixture 和 owner-boundary 测试同步更新；A 模块的 history 表属于 schema v3，不在 B 内。

### 3. 首次扫描与文件夹管理

- 扫描状态提升为应用级状态，不再只属于文件夹页：顶栏始终有一个紧凑的“扫描中 N”入口；首页有扫描卡；文件夹页有完整扫描面板。
- 扫描卡显示当前文件夹、已扫描、已加入、更新时间/耗时、取消按钮。数量未知时不画假进度条，用已扫描计数 + 活动指示。
- 欢迎卡保留到第一条内容出现；扫描中空首页显示“欢迎 + 扫描卡”，不显示空白。
- 取消扫描在首页、顶栏、文件夹页都可用；取消后保留已有片库条目和播放进度。
- 扫描完成摘要进入应用级 notice，至少保留到用户主动关闭或离开当前页；列表刷新不得覆盖摘要。
- 扫描中的列表刷新改为原地更新，不再每 350ms 用 8 个骨架替换整个网格；只有首次加载使用骨架。
- 文件夹页的扫描结果面板可折叠/关闭，不再永久占据首屏。
- 文件夹卡增加“重新扫描”和“移除”；顶部提供“重新扫描全部”。单个视频导入形成的文件夹显示说明，不提供“重新扫描”之外的额外承诺。
- 移除对话框明确统计与后果，文案见第 7 节；失败时错误留在对话框内，可重试或取消。
- main 进程增加单实例锁；第二次启动聚焦已有窗口，不并行打开第二个扫描器。

### 4. 导航、搜索与滚动

- 视图状态固定为：首页、作品列表、单集列表、搜索结果、详情、文件夹；播放器是独立视图。
- 详情记录进入时的页面（首页/作品列表/单集列表/搜索/剧集卡），返回时回到该页面并恢复滚动位置；顶部导航保持该页的高亮。
- 作品列表/单集列表的翻页、筛选、排序、新搜索都滚到顶部；从详情返回时恢复列表位置。
- 顶栏在滚动时保持可见；作品列表的筛选条在 1040/900 高度允许时保持可见，具体粘性布局以设计稿和 900×640 验收为准。
- 搜索是独立视图：标题“搜索「X」”，显示数量、筛选和返回路径；“清除搜索”回到搜索前的视图，不默认回首页。
- 详情和播放器不显示会静默改库的全局搜索框；详情页只保留一个明确的搜索入口（图标/按钮/可提交的搜索框），提交后进入搜索结果视图并保留返回路径；输入过程中不得改变背后的片库查询。
- 搜索筛选规则：默认沿用当前类型筛选，并提供“在全部类型中搜索”；清除筛选后仍保留查询。切换顶部导航（首页/片库/文件夹）时清空当前 query，避免旧搜索词在选中 tab 下偷偷生效；在搜索结果视图内切换筛选则保留 query。
- 分页提供首页/上一页/页码/下一页/末页 + “第 X / Y 页” + 跳页输入；作品 24/页，单集 24/页，不改变现有页大小以控制范围。
- 文件夹页成为顶部“文件夹”一级页面，有自己的空状态、扫描状态和返回语义；不再借用“全部”高亮。

### 5. 详情与播放连续性

- 作品卡点击打开详情，代表 media ID 决定默认选中集；详情标题使用 Collection 标题。
- 详情标题允许换行，最长可完整阅读；极端长标题用较小字号/两行 + 展开，不省略到无法辨认。
- 详情加载使用本页骨架；失败显示本页错误状态（重试/返回），不保留上一部作品的封面、标题和可点播放按钮。
- 剧集详情显示总集数、已看集数、当前集、每集已看/进度；季度切换只在多季时出现。
- 主按钮语义：可续播时“继续播放 · 第 2 季 第 3 集”；已看完时“重新播放”；无进度时“播放”。次按钮“从头播放”只在有进度时出现。
- 播放器记录打开时的页面：从详情打开，关闭回详情并恢复选中的集与滚动位置；从首页 hero 打开，关闭回首页；从片尾“返回剧集列表”回详情。
- 关闭按钮的可见/读屏文案随返回目标变化：“返回详情”或“返回首页”，不统一写“返回片库”。
- 片尾面板显示“下一集：第 2 季 第 4 集 · 集名”，按钮为“立即播放 / 取消 / 返回详情”；电影不显示“返回剧集列表”。
- 播放设置改为有标题的分组面板：播放速度、音轨、字幕、外挂字幕；支持关闭按钮、Esc、点外关闭，打开时焦点进入面板，关闭后回设置按钮。
- 播放失败在播放器画面内显示原因和“重试/返回”，不只写 sr-only 状态。
- 进度/音量统一为自绘滑杆；进度支持 hover 时间提示（至少显示目标时间），键盘步进与按钮步进统一为 10 秒。
- 播放结束倒计时可被读屏播报一次“10 秒后播放下一集：X”，不每秒刷屏。

### 6. 空、错、离线与删除

空状态矩阵：

- 无文件夹、无作品：欢迎卡 + 添加文件夹/添加单个视频。
- 有文件夹、0 作品：说明“这个文件夹还没有支持的视频”，提供“重新扫描 / 添加其他文件夹 / 查看支持的格式”。
- 搜索无结果：显示查询词、“清除搜索”、有筛选时“在全部类型中搜索”、关键词建议。
- 筛选无结果：显示当前筛选、“查看全部”、清除筛选。
- 列表加载失败：本页错误状态 + 重试；不显示空状态伪装成“没有内容”。

错误与离线：

- 存储错误：普通话说“片库文件暂时无法读写”，提供“重试 / 重启应用 / 复制诊断信息”；错误代码收进“技术详情”，不是主文案。
- 启动时 SQLite/worker 失败：main 显示可见错误窗口或对话框，提供“重试启动 / 退出 / 复制诊断信息”，不再静默 `exit(1)`。
- 文件夹离线：作品卡/继续卡显示“文件夹离线”徽标；详情横幅说明“重新连接驱动器或网络位置后，在文件夹页重新扫描”；播放/从头按钮禁用，附近写原因，不写“可继续”。
- 离线横幅提供“查看文件夹”，返回路径保留详情。

删除：

- 对话框标题“移除「文件夹名」？”；正文“将从片库移除 N 部作品、M 集，并删除这些视频的观看进度。不会删除源文件。”
- 取消为默认焦点；确认按钮为 destructive 红色，文案“移除并删除进度”。
- 删除失败时对话框不关闭，显示错误和“重试/取消”。
- 不做撤销（重新扫描代价高）；用明确文案和 destructive 样式防止误操作。

### 7. 设计系统与原生控件

- 保留 Soft Cinema token：`#0e0e10` 底、`#19191d` surface、lavender 主色、pink/blue/orange/mint 动态 tone、胶囊/大圆角。字体与真实应用一致：`Nunito, "Microsoft YaHei UI", "PingFang SC", "Noto Sans SC", system-ui, sans-serif`；Nunito 优先，正文、标题、数字共用同一字体栈，随包内嵌 `nunito-latin.woff2`，不再把中文写成第一优先。
- 新增共享原语：按钮（primary/secondary/destructive/ghost）、图标按钮、Menu trigger、Menu popover、Range、ScrollArea、Dialog、Notice、Pagination、作品卡、单集行。
- 所有选择（排序、音轨、字幕、倍速）改用**应用内菜单**：trigger 统一高度/字体/圆角/自绘 chevron，弹层为 `--surface-2` 底、18px 圆角、lavender 选中态，与全站同色；不再出现系统弹层。
  - 语义：`role="listbox"` + `role="option"` + `aria-selected`，trigger 带 `aria-haspopup="listbox"` / `aria-expanded`；打开时焦点进入当前项（无选中则首项），菜单内方向键 / Home / End 移动，Enter/Space 选择，Esc/Tab 关闭并把焦点还给 trigger。
  - 理由：Windows 的系统弹层无法用 CSS 改样式，浅色系统菜单与深色界面并置会像“另一套应用”。代价是失去原生弹层的部分平台行为（如系统级输入法联想、部分辅助技术的特化播报），需在验收里逐项确认。
- 音量与进度共用一套自绘 Range；原生 input 保留在透明层，负责键盘和读屏。
- 滚动条统一深色细条；横向片架增加左右翻页按钮，不只依赖滚动条。
- 所有图标改 SVG：窗口控制、±10 秒、添加、搜索、chevron；不再使用字符图标。
- 搜索框显式隐藏 WebKit 原生清除按钮，只保留自绘清除；搜索放大镜是可点击按钮（聚焦/提交），不是装饰字符。
- 搜索框自身 `border:0 / outline:0 / box-shadow:none`（含 `:focus`、`:focus-visible`）；焦点只由外层胶囊的 `inset 2px lavender` 表达。鼠标点击控件不出现矩形焦点框，只有键盘 `:focus-visible` 才画环；Range 的外环由 `:has(input:focus-visible)` 控制。
- 单集行使用 `button` + `aria-current="true"` 表达当前集，不用 `aria-selected`；季度切换用 `aria-pressed`。
- 焦点环 3px lavender、偏移 3px；详情打开焦点到标题，对话框默认焦点到取消，返回恢复原卡片。
- 移除卡片网格的整体 `aria-live`；用独立的“结果数量”live region 按 500–800ms debounce 播报。扫描进度按里程碑（开始/取消/完成）和最多每秒一次播报；片尾倒计时只播报一次“10 秒后播放下一集：X”。
- 高对比度：renderer 消费 appearance 状态，`forced-colors` 下使用系统色；不只让 main 选择窗口材质。
- 帮助/视图入口提供 100/125/150% 界面缩放并持久化；缩放后 1040/900 布局仍可用，不靠放大窗口掩盖溢出。
- 动效与降级：按第 8 节执行；默认跟随系统“减少动画”，产品可提供完整/减弱/关的手动覆盖；焦点环永不动画，所有信息性动效都有静态等价文案。
- 1040×720 与 900×640 都要验证主要按钮、筛选、分页、播放设置不被裁切；最小窗口下允许压缩标签，不隐藏关键动作。
- 新增可见的“帮助”入口（快捷键、关于、数据位置说明），不要求完整原生菜单；如果保留自绘标题栏，帮助入口放在页头菜单。

### 8. 动效、原生手感与字体

动效的定位是“剪辑语言”，不是 App 动画：**默认硬切，只在需要解释因果时用一次淡入/位移；不表演、不循环装饰。**

- Token：`--mo-1 90ms` 按下反馈、`--mo-2 140ms` 状态变化、`--mo-3 200ms` 视图转场（返回 160ms）、`--mo-4 420ms` 一次性叙事（每会话最多一次）。
- 缓动：默认 `cubic-bezier(.2,.7,.3,1)`；同区域展开 `cubic-bezier(.4,0,.2,1)`；进度/倒数只准 `linear`。
- 五个原型：
  1. **反馈**：按钮/行/卡 hover、按下、`aria-pressed`，90–140ms 背景色 + 1px 下沉，不做圆角变形。
  2. **状态变化**：筛选、计数、已看标记，140ms 交叉淡入；数字上移淡入，不整行重排。
  3. **视图转场**：首页→详情、详情→播放器，200ms 海报共形到详情头，其余内容独立淡入；全站唯一共享元素过渡；返回 160ms 反向。
  4. **过程**：扫描/导入，无假进度，活动点 + 已扫描计数；完成摘要一次性展开后静止。
  5. **叙事**：首次出现第一条内容、片尾倒数，每会话最多一次；倒计时环 linear 消耗，可被“立即播放”打断。
- 明确不做：网格重排、逐卡 stagger（8000 条不做入场编排；上限 6 个元素 / 144ms）、骨架闪烁、hover 圆角变形、波浪流动、水位上涨、饼干旋转、任何 infinite 装饰。唯一的循环留给“扫描中”活动指示，因为它表达活动，不表达进度。
- 性能：只动 `transform` / `opacity`（`filter` 仅限 ≤120px 小面积）；每视图最多 1 个并发动画；播放路径 ≤200ms 且可跳过；`will-change` 只在转场期间挂、结束即摘；不引入动画库。
- 四档行为：**跟随系统**（默认，系统 reduce → 减弱）、**完整**（仅用于评审/手动覆盖）、**减弱**（去位移/缩放/循环，只保留颜色与透明度）、**关**（全部瞬时）。产品至少提供“跟随系统”；手动覆盖存应用偏好，不写媒体表。
- 降级不丢信息：扫描显示“扫描中 · 已扫描 N”+静态点；片尾显示完整“10 秒后播放下一集：X”；已看/进度用标签与静态进度表达。`forced-colors` 同样降级，不依赖颜色差。
- 焦点环永不动画；`prefers-reduced-motion` 下焦点仍然瞬时可见。转场中点“继续播放”必须立即让位，不能阻塞播放。

原生手感（“像 App，不像网页”）：

- `body` 使用 `user-select:none`、`-webkit-user-drag:none`、透明 `::selection`；`input/textarea` 恢复 `user-select:text`，保证输入内容可选取编辑。
- renderer 全局拦截 `contextmenu`、`dragstart`，并拦截非输入区域的 `selectstart`；输入框内放行 `selectstart`，避免无法选字。全局拦截右键的代价是鼠标右键粘贴菜单也没有了（Ctrl+V 仍可用）；本轮接受，应用内文本菜单另行决定。
- 鼠标点击控件不出现 `:focus` 矩形边框；只有键盘 `:focus-visible` 画 3px lavender 环。搜索输入框自身无边框，焦点由外层胶囊表达；Range 的焦点环由 `:has(input:focus-visible)` 驱动。
- 全站字体与应用一致：Nunito 优先，中文回落到系统字体；内嵌 `nunito-latin.woff2`；正文、标题、数字共用同一字体栈，不再出现“有的地方是 Nunito、有的地方是雅黑”。
- 选择控件继续使用第 7 节的应用内 Menu；播放设置面板空间不足时使用同一层级的 inline chip 组，避免 popover 被面板裁切。

## Testing Decisions

好的测试只验证外部行为：用户能看到的作品卡数量、标题、计数、按钮、滚动位置、焦点、对话框文案和错误恢复；不测试私有 SQL、内部函数名、组件树或调用次数。

复用现有 seam，不新增测试框架：

1. **Local library database facade（真实 SQLite）**  
   验证作品聚合、续播选择、每集状态、搜索命中、source 过滤、作品计数、空/离线、排序；另外验证 B0：`<premiered>`/`<releasedate>` 解析为 `YYYY-MM-DD`、非法日期为 null、migration v2 幂等、`released_desc` 日期降序且 null 排最后、不能用 `year` 顶替日期。使用现有数据库 smoke 的临时 profile 和真实 worker，不 mock SQLite。

2. **Production app smoke（真实 main + worker + 窗口）**  
   使用现有 `test:local-library-app` 路径和隔离 profile，增加一条作品 fixture：1 部电影 + 1 部 3 集剧 + 1 个未分类文件；另一组足够多的电影用于分页。覆盖：
   - 首次空态、欢迎卡、扫描中/取消/完成摘要；
   - “剧集”只出现 1 张剧卡，标题、3 集、已看计数；
   - 打开剧集、选 E02、播放、关闭回详情且 E02 仍选中；
   - 片尾显示下一集名称；
   - 搜索剧名/单集名，作品卡只出现一次并标出匹配集；
   - 切“单集”看到 3 集；
   - “继续观看”不足 30 秒不出现，超过阈值只出现一条作品卡，计数与可翻页卡片一致；

   - 分页首页/末页/跳页、筛选/搜索回顶部、详情返回恢复滚动；
   - 移除对话框包含“观看进度”和 destructive 按钮；
   - 离线作品卡/详情文案一致；
   - 存储错误按钮包含重试/重启/复制诊断；
   - 详情打开焦点在标题，列表不再整页 live 播报；
   - 排序菜单在 B0 migration 后包含“最近发布”；没有日期的条目仍可按该排序，位置在已发布日期之后，不伪造日期；
   - B0 后按“最近发布”排序，验证日期顺序正确，旧数据/无日期条目不会跑到已发布日期前面；
   - 1040×720 与 900×640 截图。

3. **Window smoke（纯渲染与原生手感）**  
   只在不需要 SQLite 的视觉/交互状态使用：Menu trigger/popover、Range、播放结束按钮的 computed style，搜索清除、空/错/离线文案，菜单的方向键 / Esc 与焦点回归；另外验证：
   - 0 个原生 `<select>`；菜单焦点契约；
   - 鼠标点击控件时 `:focus-visible` 为 false、无矩形 outline；
   - 文本 `contextmenu` / `dragstart` / `selectstart` 被 `preventDefault`，输入框内 `selectstart` 放行；
   - 正文 `user-select:none`，输入框 `text`；
   - 字体栈为 Nunito 优先，`document.fonts.check` 能命中内嵌字体；
   - 可见窗口中动效只动 `transform` / `opacity`，转场 ≤200ms，焦点环无动画；`prefers-reduced-motion` 降级后仍有静态等价文案。
   - 不要用隐藏窗口断言 CSS 动画（Chromium 不推进帧，会得到假阴性）。

4. **Contract tests**  
   新增作品 DTO 的 owner-boundary 测试：无绝对路径/相对路径；分页、filter、sort、query、source 校验；`released_desc` 只在 B0 schema 后接受；`premieredDate` 格式校验；新 IPC 的拒绝路径；`LocalMediaDetail` 每集状态不包含路径。

5. **视觉证据**  
   1040×720 与 900×640 各一套截图；设计稿为 14 画板 / 42 状态，至少覆盖高风险状态（播放设置 900、长标题、空/错/离线、移除失败）。对比度用实际 hex 计算；高对比度与 150% 界面缩放至少做一次人工检查。截图不替代真实播放/DWM 验收，也不替代动效的可见窗口测量。

需要更新的现有测试包括：错误卡片按钮从只有“重试”改为多动作；`filter=show` 的结果从单集改为作品；长标题断言从“截断”改为“完整可读”；关闭播放器断言从“回片库”改为“回详情”；扫描状态在默认宽度可见。

## Out of Scope

- NAS、账号、Session、登录恢复、NAS 协议与回滚路径。
- 刮削/在线 metadata provider、自动 watcher、文件系统监听。
- 除 B0 的 `collections.premiered_at` 外，不做其它 SQLite schema 变更；单个视频导入仍沿用父文件夹 Source 契约。
- 原生播放引擎、硬解、DWM、HDR、音频直通、字幕渲染能力。
- 新前端框架、组件库、状态管理库、虚拟列表库。
- 中文拼音排序、全文检索（plot/演员/类型）、删除撤销、多窗口、云同步。
- macOS 视觉验收；Windows 先验收，macOS 单独记录。
- 装饰性动效（hover 圆角变形、波浪流动、水位上涨、饼干旋转）；这些仍按 soft-cinema 的推迟决定处理。
- 应用内文本右键菜单；全局拦截右键后鼠标粘贴菜单缺失是已知取舍，本轮不补。
