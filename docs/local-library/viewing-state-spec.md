# 观看记录与整理助手（Viewing State）

Status: ready-for-agent  
Triage: ready-for-agent  
Date: 2026-11-08  
Scope: 本地片库内的观看状态记录、删除即遗忘、离线/缺失边界、片库“整理”队列与阈值设置。  
Related: 作品级 Collection 契约与界面基础见 `docs/local-library/ux-rework-spec.md`（B，先做）；本模块（A）不新增一级“档案”页面，控件/动效/字体复用 B 的决定。

## Problem Statement

用户的磁盘空间长期紧张，经常删除视频文件，甚至整个删除包含视频、NFO、海报的文件夹。片库里有大量类似 AV 的单文件作品，用户需要打开看一下才能决定是否删除，效率很低。

现有本地片库只保存“最后位置、是否看完”，没有打开次数、累计观看时长、上次打开时长、完成次数等长期状态；删除来源时还会把播放进度一起删除。用户需要的是：

- 在当前文件还在盘上时，自动记住自己的观看行为；
- 用这些行为帮助判断“这部值不值得留”；
- **一旦用户删除影片/文件夹，就代表不再需要它，对应记录也应一起消失**；
- 不做跨删除的全局统计，不做“已删除作品档案”，不接网上评分。

这不是一个“统计报表”需求，而是一个**当前片库的观看状态 + 删除决策助手**。

## Solution

在本地片库内增加一个独立的领域模块，产品上叫“观看记录 / 整理”，不新增一级“档案”页面：

- **观看记录**：每个当前作品详情显示打开次数、有效观看次数、累计观看时长、完整看完次数、上次打开时间、上次打开时长、平均每次时长、完成率、检查型打开占比、文件大小与 GB/小时。
- **整理助手**：片库内增加“整理”入口，按规则列出当前文件中的候选，给出“为什么推荐”的数字和规则名；不自动删除文件，只生成待删清单，最终由用户在资源管理器删除。
- **删除即遗忘**：删除影片、删除文件夹、移除来源时，级联清理该文件的会话和聚合记录；不保留标题、封面缓存或“已删除档案”。
- **离线不等于删除**：来源暂时不可用时保留记录；整个来源不可用时询问“暂时断开 / 已删除”，只有用户确认已删除才清理。
- **阈值可设置**：默认“标准”预设，另提供保守/积极预设和完整高级自定义；候选卡始终显示当前阈值，避免黑箱推荐。
- **无全局统计**：不保存跨删除的总观看时长、年度统计等；所有汇总只针对当前片库内仍存在的文件，“待删清单 N GB”也是当前候选的实时求和。

## User Stories

1. 作为片库主人，我希望打开视频时自动开始记录，不需要手动打卡，以便长期使用没有额外负担。
2. 作为片库主人，我希望区分“打开次数”和“有效观看次数”，以便“打开看一眼”不会被误算成看过。
3. 作为片库主人，我希望看到每部作品的累计实际播放时长，以便知道我在这部片上投入了多少时间。
4. 作为片库主人，我希望看到完整看完次数和完成率，以便判断这部片是否真的吸引我。
5. 作为片库主人，我希望看到上次打开时间和上次打开时长，以便知道多久没碰它、上次看了多久。
6. 作为片库主人，我希望上次打开时长同时显示“实际播放”和“停留时长”，以便区分真看和挂着。
7. 作为片库主人，我希望看到平均每次观看时长，以便理解自己的使用习惯。
8. 作为片库主人，我希望看到“检查型打开”占比，以便知道我是不是经常只是打开看看。
9. 作为片库主人，我希望看到文件大小和“GB/小时”，以便判断这部片占的空间值不值。
10. 作为片库主人，我希望作品详情里有一块“你的记录”，以便不用去单独页面查。
11. 作为片库主人，我希望没有观看记录时显示“还没有记录”，而不是一堆 0，以便界面干净。
12. 作为片库主人，我希望片库里有“整理”入口，以便从当前文件里找删除候选。
13. 作为片库主人，我希望候选卡明确写出命中的规则和数字，以便我信任或否定这个推荐。
14. 作为片库主人，我希望按“从未打开 / 只看了一眼 / 打开少且大 / 大文件低回报 / 看完但低回访”分类，以便不同情况分开处理。
15. 作为片库主人，我希望“文件大”有明确阈值，而不是一个形容词，以便我知道为什么它被选中。
16. 作为片库主人，我希望“打开少”有明确次数，并和“多久没打开”一起判断，以便不同大小的片库都能用。
17. 作为片库主人，我希望“很久没看”有明确天数，以便候选不会每天变动。
18. 作为片库主人，我希望使用“保守 / 标准 / 积极”预设，以便不用先面对十几个数字。
19. 作为片库主人，我希望在高级设置里修改每个阈值，以便适配我的片长、码率和库大小。
20. 作为片库主人，我希望可以单独开关 A–E 规则，以便不想看“低回访”时直接关掉。
21. 作为片库主人，我希望“稍后”能让候选消失一段时间，以便整理页不会每天推同一批。
22. 作为片库主人，我希望“保留”能让作品一段时间内不再出现，以便我明确不想删的片不被反复推荐。
23. 作为片库主人，我希望把候选标成“待删”，最后汇总成清单和总 GB，以便一次性处理。
24. 作为片库主人，我希望待删清单只包含当前还在盘上的文件，以便数字不会包含已删除作品。
25. 作为片库主人，我希望从整理队列直接打开“检查模式”，播放器上显示第几次打开、累计多久、上次多久，以便快速判断。
26. 作为片库主人，我希望检查模式可以一键“保留 / 待删 / 稍后”，以便不用回到资源管理器再记一遍。
27. 作为片库主人，我希望 App 不自动删除文件，只给出清单和“在资源管理器中显示”，以便误判不会造成数据损失。
28. 作为片库主人，我希望删除单部影片后，它的观看记录一起消失，以便删除是干净的。
29. 作为片库主人，我希望删除整个文件夹后，其中所有作品的记录一起消失，以便不留下隐私残留。
30. 作为片库主人，我希望移除来源时明确“会删除观看记录”，而不是偷偷保留，以便我知道后果。
31. 作为片库主人，我希望来源只是离线时保留记录，以便硬盘没接上不会丢历史。
32. 作为片库主人，我希望整个来源不可用时被问“暂时断开还是已删除”，以便由我决定是否清理。
33. 作为片库主人，我希望扫描确认文件缺失时清理该条记录，以便删除后不残留。
34. 作为片库主人，我希望删除后重新加入同一文件时从新记录开始，以便不复活旧历史。
35. 作为片库主人，我希望不保留任何跨删除的全局总时长/年度统计，以便产品尊重“删除即不再需要”。
36. 作为片库主人，我希望不接网上评分、番号库或在线刮削，以便指标只来自我的体验。
37. 作为片库主人，我希望观看记录只存在本机，日志不写标题，以便这类内容不被意外暴露。
38. 作为片库主人，我希望旧版已有的播放进度只显示为“上次看到（旧记录）”，不伪造次数和累计时长，以便数据诚实。
39. 作为片库主人，我希望 8000 条片库下整理页仍然快速打开，以便大库可用。
40. 作为键盘用户，我希望整理队列和检查模式可以用键盘完成，以便不用鼠标逐项点。
41. 作为小屏用户，我希望 900×640 下整理页和详情记录块不被裁切，以便最小窗口可用。
42. 作为维护者，我希望会话与聚合只通过 local library owner 写入，renderer 不接触路径，以便保持现有安全边界。
43. 作为维护者，我希望删除/离线/缺失三种状态有明确测试，以便不会误删记录或残留隐私数据。
44. 作为维护者，我希望阈值设置存于应用偏好而不是媒体表，以便调整规则不需要 schema 迁移。
45. 作为维护者，我希望复用现有 facade/app smoke 测试，不新增测试框架，以便这次能安全交付。

## Implementation Decisions

### 1. 产品边界与位置

- 产品名使用“观看记录”和“整理”，不使用“档案 / 历史库 / 已删除作品”。
- 不新增顶部一级 tab；在片库工具带增加“整理”入口，在作品详情增加“你的记录”块。
- 整理页是片库的一个视图，不是独立页面层级；返回片库时保留筛选、页码和滚动。
- 不新增全局统计页、年度报告、跨删除总计。
- App 保持只读：不删除、不移动、不改名媒体文件；整理只生成候选和待删清单。

### 2. 记录单位

- **会话**：一次从打开播放器到关闭/结束/失败的播放尝试，记录在具体 media file 上。
- **作品记录**：MVP 以 media file 为单位；电影/AV 一文件一记录。剧集的 collection 级汇总放到后续切片，先用现有 collection/episode DTO 展示“共 N 集 / 已看 N 集”，不阻塞本模块。
- **整理候选**：以 media file 为单位，因为删除动作是文件级；剧集候选显示剧名、季集和文件名，避免只看到单集标题。
- 不使用跨删除稳定的 `history_key`；`mediaId` 只在文件存在期间作为身份，删除后记录级联消失。
- 重新加入同一文件时是新记录，不继承旧记录。

### 3. 数据模型（schema v3，增量）

新增两张表，均由 local library worker 独占写入；不改现有表字段：

- `viewing_sessions`
  - `session_id`、`media_id`（FK → media_files，ON DELETE CASCADE）
  - `started_at`、`ended_at`、`wall_sec`、`played_sec`
  - `start_position_sec`、`end_position_sec`、`duration_sec`
  - `completed`、`pause_count`、`seek_count`、`speed`
  - `close_reason`：`ended` / `user-close` / `error` / `app-quit` / `interrupted`
  - 索引：`(media_id, started_at)`、`(started_at)`
- `media_history`
  - `media_id`（PK，FK → media_files，ON DELETE CASCADE）
  - `open_count`、`effective_watch_count`、`completed_count`
  - `inspection_open_count`、`total_played_sec`
  - `first_seen_at`、`last_opened_at`、`last_played_at`
  - `last_session_played_sec`、`last_session_wall_sec`
  - `last_position_sec`、`last_duration_sec`
  - `cleanup_state`：`none` / `keep` / `snooze` / `delete-candidate`
  - `cleanup_until`、`updated_at`
  - 索引：`(last_opened_at)`、`(cleanup_state)`

迁移只新增表，`user_version` 升到 3（B 的 B0 先把 `collections.premiered_at` 升到 2）；现有 `playback_state` 不改、不删除、不用于回填次数/累计时长。旧进度只在当前作品详情作为“上次看到（旧记录）”展示。

不新增 `usage_totals` 或任何跨删除累计表。所有 source/media 删除时由外键级联清理；不保留 tombstone。

### 4. 会话采集

- 播放器宿主在 `open/ready` 时创建会话，在 `ended`、用户关闭、错误、应用退出时结束会话。
- `played_sec` 只累计实际 `playing` 时间；暂停、缓冲、全屏切换不计入。`wall_sec` 记录从打开到关闭的墙钟时间。
- 每 10 秒写一次轻量心跳（`last_heartbeat_at` 可放会话记录或内存）；应用崩溃后，下次启动把未结束会话标为 `interrupted`，按最后一次心跳结算，避免丢掉整段。
- 完成判定：播放器 `ended`，或 `duration > 0 && end_position >= 90% && played_sec >= 30`。不只看最后位置，避免拖到结尾被算成看完。
- 有效观看判定：`played_sec >= 30` 且（`duration <= 0` 或 `played_sec >= duration * 3%`）。两个条件同时满足才算有效。
- 会话开始即 `open_count + 1`；有效观看才 `effective_watch_count + 1`；`played_sec < 有效阈值` 计 `inspection_open_count + 1`。
- 播放器只把 `mediaId`、位置、时长、状态、速度等 renderer-safe 值发给 main；不传路径。

### 5. 指标定义

| 指标 | 公式 / 来源 | 展示 |
|---|---|---|
| 打开次数 | `open_count` | “打开 6 次” |
| 有效观看次数 | `effective_watch_count` | “有效观看 4 次” |
| 累计观看时长 | `total_played_sec` | “累计 1 小时 12 分” |
| 完整看完次数 | `completed_count` | “看完 2 次” |
| 完成率 | `completed_count / effective_watch_count` | 无有效观看时显示“—” |
| 上次打开 | `last_opened_at` | “3 天前” |
| 上次打开时长 | `last_session_played_sec` / `last_session_wall_sec` | “上次播放 4 分钟（停留 12 分钟）” |
| 平均每次 | `total_played_sec / effective_watch_count` | “平均 18 分钟” |
| 检查型打开占比 | `inspection_open_count / open_count` | “60% 只是打开看看” |
| GB/小时 | `size_bytes / (total_played_sec / 3600)` | 未观看显示“未产生观看” |
| 文件状态 | 当前 media available + source available | “在盘 / 文件夹离线” |
| 清理状态 | `cleanup_state` | “保留 / 稍后 / 待删” |

不生成单一“个人评分”；如需个人价值，展示“投入 / 完成 / 回访”三组数字，不合并成黑箱分数。

### 6. 删除、离线、缺失

- **用户删除单文件**：扫描确认文件缺失且来源可用时，worker 在同一事务内显式删除该 media 的 `media_history` 与 `viewing_sessions`，再移除/标记 media 行；不能只把 media 标为 unavailable 后依赖外键，否则会留下记录。
- **用户删除整个文件夹**：source 变为 unavailable；不自动清空记录。片库显示“文件夹离线”横幅，并提供“暂时断开 / 已删除”两个选择：
  - 暂时断开：保留记录，来源恢复后继续。
  - 已删除：删除 source 及其 media/history/sessions。
- **用户移除来源**：明确视为删除，级联清理 source、media、history、sessions；对话框文案明确“会删除观看记录”，不提供“保留记录”勾选。
- **文件只是重命名/移动**：MVP 视为旧文件删除 + 新文件加入，记录从头开始；这是“删除即遗忘”的代价，不做跨路径身份。
- **旧版 playback_state**：只作为“上次看到（旧记录）”展示，不生成虚假的次数/累计时长；新会话从本版本开始。
- **没有全局统计**：不保留被删除作品的总量；所有聚合在当前片库内实时可见，删除后自然消失。

### 7. 整理规则与阈值

默认“标准”预设；所有阈值可改。设置只影响候选，不影响观看记录本身。

| 阈值 | 标准默认 | 范围 | 用途 |
|---|---:|---:|---|
| 新片保护期 | 30 天 | 7–90 | 规则 A/B 不碰新片 |
| 久未打开 | 90 天 | 30–365 | 规则 B/C 的常规门槛 |
| 强久未打开 | 180 天 | 90–730 | 规则 E |
| 打开少 | ≤2 次 | 0–5 | 规则 C |
| 有效观看时长 | 30 秒 | 10–120 | 有效观看 |
| 有效观看比例 | 3% | 1–20 | 有效观看 |
| 一眼上限 | 60 秒 | 10–300 | 规则 B 的“只看了一眼” |
| 低回报上限 | 10 分钟 | 1–60 | 规则 D 的“低回报” |
| 低回报打开上限 | 3 次 | 0–10 | 规则 D 的“打开少” |
| 低回访打开上限 | 3 次 | 0–10 | 规则 E 的“打开少” |
| 完整看完 | 90% | 80–100 | 完成判定 |
| 大文件 | 2 GB | 0.5–20 | 规则 A/B |
| 很大 | 5 GB | 1–50 | 规则 C/D/E |
| 超大 | 10 GB | 2–100 | 排序优先级/标签 |
| 相对大 | 前 20% | 10–30 | 片库 ≥20 文件时启用 |

预设：

| 预设 | 大/很大/超大 | 保护/久未/强久未 | 打开少 | 有效观看 | 完成 |
|---|---|---|---:|---|---:|
| 保守 | 4 / 8 / 15 GB | 60 / 180 / 365 天 | ≤1 | 30 秒 + 5% | 95% |
| 标准 | 2 / 5 / 10 GB | 30 / 90 / 180 天 | ≤2 | 30 秒 + 3% | 90% |
| 积极 | 1 / 3 / 5 GB | 14 / 60 / 120 天 | ≤3 | 15 秒 + 2% | 85% |

预设同时调整高级阈值：一眼上限 / 低回报上限 / 低回访打开上限分别为保守 `30 秒 / 5 分钟 / 1 次`、标准 `60 秒 / 10 分钟 / 3 次`、积极 `120 秒 / 15 分钟 / 5 次`。选择“自定义”后逐项可改。

规则：

- A 从未打开：`open_count = 0` · 加入 ≥ 保护期 · `size >= 大文件`
- B 只看了一眼：`open_count >= 1` · `effective_watch_count = 0` · `total_played_sec < 一眼上限` · 上次打开 ≥ 保护期 · `size >= 大文件`
- C 打开少 + 大文件：`open_count <= 打开少` · `completed_count = 0` · 上次打开 ≥ 久未打开 · `size >= 很大`
- D 大文件低回报：`size >= 很大` · `total_played_sec < 低回报上限` · `open_count <= 低回报打开上限`
- E 看完但低回访：`completed_count >= 1` · 上次打开 ≥ 强久未打开 · `size >= 很大` · `open_count <= 低回访打开上限`（默认标记“低回访”，不写“建议删除”）

排序：C → D → A → B → E；同规则按可释放空间降序。每条候选卡显示命中的规则名、当前阈值和具体数字。

规则 A–E 均可独立开关；关闭 E 后不再出现“低回访”候选。不计算单一“推荐分”。

### 8. 设置与偏好

- 设置放在现有应用偏好模块，不新增媒体表字段：`cleanup.preset`、`cleanup.thresholds`、`cleanup.rules`、`cleanup.snoozeDays`、`cleanup.keepDays`。
- `snooze` 默认 30 天；`keep` 默认 180 天；到期后重新进入候选。
- 修改设置后在下次整理查询生效；不需要重启。
- 恢复默认按钮；设置页显示“当前规则预览”，例如“按当前设置：候选 37 部 / 约 126 GB”。
- 阈值校验：天数 1–3650；次数 0–20；GB 0.5–100；百分比 1–100；秒 10–300。

### 9. 整理 UI

- 片库工具带增加“整理”按钮/筛选入口；不新增一级 tab。
- 整理页包含：
  - 顶部：“候选 N 部 · 约 X GB” + “规则”入口。
  - 规则筛选：A–E + 清理状态。
  - 候选列表：封面、标题、大小、规则名、关键数字。
  - 每项动作：保留 / 稍后 / 待删 / 打开检查。
  - 底部“待删清单 N 项 · X GB” + “查看清单”。
- 作品详情“你的记录”块：
  - 有记录：打开/有效/累计/看完/上次/上次时长/完成率/GB 小时。
  - 无记录：一句话 + 播放按钮。
  - 离线：保留记录 + “文件夹离线”原因，不显示可播放。
- 检查模式：播放器顶部叠一条“第 4 次打开 · 累计 18 分钟 · 上次 3 天前”，关闭时提供“保留 / 待删 / 稍后”；只在从整理队列进入时出现，不打扰日常播放。
- 不显示“已删除作品”或“历史档案”；删除后条目和记录一起从片库消失。
- 900×640 下整理页、详情记录块、待删清单不裁切；长标题换行。

### 10. 隐私与性能

- 全部本地；不联网、不调用在线评分/番号库/刮削。
- 日志只记录操作、计数、错误码，不记录标题、文件名或完整路径。
- 删除即级联清理，不在数据库或缓存里留标题、封面。
- `viewing_sessions` 按 `media_id` 索引；整理候选只查当前可用 media + 聚合表，不加载全部会话到 renderer。
- 大库（8000 文件）下整理页分页或分批；候选查询有上限，不阻塞片库。
- 不新增后台进程或第二个 SQLite；由现有 utilityProcess owner 执行。

### 11. 交付切片

1. **Ledger 核心**：schema v3、会话采集、`media_history` 聚合、级联删除、详情“你的记录”。
2. **整理规则与设置**：偏好结构、三档预设、A–E 规则、候选查询、整理页、待删清单。
3. **检查模式与收口**：播放器叠层、保留/稍后/待删、键盘、900×640、隐私日志、完整 app smoke。

系列 collection 级汇总作为后续切片；MVP 先解决单文件 AV/电影的痛点。

## Testing Decisions

好的测试只验证外部行为：详情页显示的数字、整理候选和原因、删除后记录是否消失、离线是否保留、设置是否改变候选；不测试私有 SQL、内部函数名或调用次数。

复用现有 seam：

1. **LocalLibraryDatabase facade + 真实 SQLite**  
   验证：
   - 打开/有效观看/完成/检查型计数；
   - 累计时长、上次打开、上次时长；
   - 删除 media/source 后 history/sessions 级联消失；
   - 离线不清、扫描确认缺失才清；
   - 重新加入产生新记录；
   - 无路径/无标题泄漏；
   - 8000 条下候选查询有界。

2. **Production app smoke（`test:local-library-app`）**  
   用真实 main + worker + 隔离 profile：
   - 播放、暂停、拖动、关闭，详情出现正确记录；
   - 从整理页打开检查模式，标记保留/稍后/待删；
   - 修改预设/自定义阈值，候选列表变化且卡片显示规则；
   - 删除文件后重新扫描，记录消失；
   - 来源离线时记录保留；选择“已删除”后清理；
   - 移除来源后记录消失；
   - 900×640 不裁切。

3. **Window smoke（纯渲染）**  
   只补详情记录块、整理页、设置表单的渲染和键盘状态；不重复完整旅程。

4. **Contract tests**  
   新增 history DTO 无路径；偏好 schema 校验；规则参数边界；删除级联的 owner 边界。

5. **Player session tests**  
   用现有 player host 测试 seam 或模拟事件验证：会话开始/结束、暂停不计时、seek 不伪造完成、崩溃恢复为 interrupted。

现有测试要更新：`removeSource` 删除记录的行为（现在与用户意图一致，需断言级联）；详情/片库错误按钮不变；本模块不改变 UX rework 的既有断言。

## Out of Scope

- 跨删除的全局统计、年度报告、累计总时长永久保留。
- 已删除作品档案、tombstone、重新加入后恢复旧记录。
- 自动删除文件、移到回收站、批量文件操作。
- 在线评分、番号库、在线刮削或任何网络元数据。
- 云同步、导出、跨设备历史。
- 剧集 collection 级完整汇总（MVP 后补）。
- 控件/动效/字体/原生手感由 UX rework（B）负责；A 不另做一套 UI 基础。
- macOS 视觉验收、真实播放/硬解/DWM 验收。

## Further Notes

- 这个模块的前提是“删除即遗忘”，与上一版“档案留存”建议相反；实现时不要引入 `history_key` 跨删除或 `usage_totals`。
- 依赖 UX rework（B）的 Collection/作品身份与界面基础；按用户决定先做 B，A 随后。文件级 AV/电影可先做，剧集汇总等 Collection 契约稳定后再补。
- 阈值默认“标准”，但所有数字可设置；候选卡必须显示命中的规则和当前阈值。
- 交付顺序与 schema：B 先做 B0 `collections.premiered_at`（schema v2），再做 B 核心；A 随后新增 schema v3（viewing_sessions / media_history）。两者都改 local library worker，不能并行改同一个 owner；migration 必须连续评审，避免版本号冲突。
- 仓库未配置 issue tracker / triage 词表；本文件头部标记 `ready-for-agent`，发布前运行 `/setup-matt-pocock-skills` 或指定 tracker。
- 真实用户媒体、真实播放、删除故障注入、DPI/150% 与读屏仍需单独验收；本 spec 不把这些写成已完成。
