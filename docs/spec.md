# z-video 首版 Spec：Slint / Rust 局域网影视客户端

状态：需求与验收边界已确认，尚未实现。日期：2026-10-16。

## Problem Statement

用户主要使用极空间的“极影视”，希望拥有聚焦影视的桌面应用：片库浏览与详情界面精致、播放和续播可靠，同时减少开发语言、工具链及无关功能的负担，并控制运行资源和磁盘占用。

原客户端包含大量 NAS 管理功能；用户不需要在新客户端重新实现这些功能。现有逆向资料已证明官方客户端可以登录并播放，但还没有证明新应用可以独立完成局域网连接、获取有效播放流及原生画面集成。

## Solution

提供基于 Slint GUI 和 Rust 业务核心的 Windows 桌面应用。用户在本机登录自己的 NAS，浏览已有 Media library，进入 Collection 详情、选择 Episode、开始 Playback session，并将观看进度同步至 NAS，以便再次打开时续播。

首版保证局域网使用，以 NAS 现有片库为主要事实来源，Windows 先交付，先个人自用。macOS 保持架构兼容但延后真实运行验收。预留 Scraper plugin 的数据与调用边界，首版不实现插件运行时。

本 spec 固定已讨论的产品行为和实现约束；播放引擎、协议未验证字段与渲染集成需要在开发中取得证据，不将候选方案写成已通过能力。

## User Stories

1. As an 极空间用户, I want 在局域网连接自己的 NAS, so that 我可以在家中直接浏览和观看影视。
2. As an Account 持有人, I want 在本机输入账号密码并完成所需短信验证, so that 我不必将凭证交给开发助手或人工写入配置。
3. As an Account 持有人, I want 在登录失败、验证码失效或 Session 过期时看到可理解的状态并重新登录, so that 我知道下一步如何恢复访问。
4. As an Account 持有人, I want 客户端遵守 NAS 对当前 Account 的可见范围, so that 我看到的是该账号有权访问的内容。
5. As an 影视观众, I want 查看 NAS 现有分类和 Media library, so that 我不需要重新扫描和建立另一套片库。
6. As an 影视观众, I want 按需浏览海报和标题, so that 片库变大时仍能操作界面而不一次加载所有图片。
7. As an 影视观众, I want 查看 Collection 的已有简介和元数据, so that 我能判断要看什么。
8. As an 影视观众, I want 查看 Collection 下的 Episode 并手动选择, so that 我能播放目标影片或指定剧集。
9. As an 影视观众, I want 从详情页直接开始播放, so that 片库到播放的操作连续且明确。
10. As an 影视观众, I want 在 Slint 应用窗口中看到视频和可操作的播放控制层, so that 我不用依靠官方客户端播放窗口完成观看。
11. As an 影视观众, I want 暂停和继续播放, so that 我可以中断观看而不丢失当前播放位置。
12. As an 影视观众, I want 拖动到目标播放位置, so that 我能跳过或重看片段且不会被旧进度回调拉回。
13. As an 影视观众, I want 在具备支持能力的硬件上对常用素材使用硬件解码, so that 播放时避免不必要的 CPU 开销。
14. As an 影视观众, I want 在媒体提供多个音轨时切换音轨, so that 我可以选择需要的语言或版本。
15. As an 影视观众, I want 选择媒体内嵌字幕或可用外部字幕并关闭字幕, so that 我能使用适合自己的观看方式。
16. As an 影视观众, I want 进入和退出全屏时保留画面、位置和控制能力, so that 窗口变化不会打断观看。
17. As an 影视观众, I want 在加载、缓冲、播放失败或 NAS 断开时看到相应状态, so that 我能区分等待和失败。
18. As an 影视观众, I want 播放位置同步到 NAS, so that 我的观看进度可以在既有片库中保存。
19. As an 影视观众, I want 关闭并重新打开应用后读取 NAS 保存的位置并续播, so that 续播不依赖上一次进程中的内存状态。
20. As an 影视观众, I want 切换 Episode 时进度和音字幕状态归属正确, so that 旧 Playback session 的回调不会覆盖当前影片。
21. As an 桌面用户, I want 网络请求、图片加载和媒体工作期间界面仍可操作, so that 片库和播放控制不会因后台工作卡住。
22. As an 桌面用户, I want 海报与本地缓存受到容量约束, so that 应用不会随使用时间无限占用磁盘和内存。
23. As an Account 持有人, I want 日志与开发资料省略凭证和私密媒体地址, so that 排查问题时不会泄露自己的 Session 或影片信息。
24. As an Windows 用户, I want 首版在 Windows 真机运行并记录支持范围, so that 我能使用已验证的功能而非仅看跨端承诺。
25. As an 未来 macOS 用户, I want 平台差异集中处理, so that 后续适配不必重写 NAS 与片库业务核心。
26. As an 不需要刮削的用户, I want 未安装 Scraper plugin 时仍可完整浏览和播放, so that 可选能力不会成为核心应用依赖。
27. As an 未来刮削扩展使用者, I want 元数据提供者返回带来源的候选供我确认, so that 我可以选择结果并由核心控制合并保存。

上述“未来”故事仅约束预留边界，不要求本次交付 macOS 应用或可执行插件。暂停/继续、加载/失败状态等是播放闭环的必要交互细化；自动连播、搜索系统或额外媒体管理不由此扩充。

## Implementation Decisions

### GUI 与执行结构

采用 Slint 声明式 GUI 与 Rust 业务核心。首选一个应用进程、一个窗口和一个播放引擎；片库和播放是应用内的不同界面状态。新增进程或运行时须由真实平台集成约束或当前产品需求证明必要。

Slint 负责展示、交互和播放控制层；Rust 协调会话、网络、模型、缓存及播放。网络、图片解码和媒体工作不阻塞 UI 线程，异步结果正确派发至 UI。视频走原生渲染路径，避免 CPU 逐帧读取再交给 GUI。

### NAS 与数据归属

NAS 模块集中管理连接、Account/Session、分类、Collection、Episode、有效流地址及观看进度。首版只保证局域网业务访问；登录是否依赖云服务以真实流程为准，不承诺纯离线鉴权。

NAS 保持 Media library 与观看进度的主要事实来源；本地保存设置、安全凭证和限额缓存。首版不建立独立扫描、索引或多端数据同步系统，也不因通用性提前增加数据库或多 NAS 提供者框架。

参考接口目录描述特定版本客户端构造过的请求，不等于完整后端规范。方法、编码、鉴权位置和返回字段按真实调用核对；不统一猜测为 Bearer token，也不将会话恢复接口直接当作 token 刷新接口。

### 播放

libmpv 是优先评估候选，未决定依赖版本、绑定、图形后端或分发构建。选择前先证明应用可独立获取有效流，并在 Slint 窗口组合视频表面、控制层和全屏。若前提不成立，记录具体限制并调整方案，不能靠复用官方进程掩盖独立链路缺失。

本地代理端口和不透明媒体路径是官方客户端当次会话产物；不写死端口、NAS 地址或用户标识，不拼造流地址。使用当前鉴权与服务返回的地址，明确媒体请求所需凭证。

Playback session 管理当前 Episode、位置、播放状态、所选音轨与字幕；停止或换片后，旧异步结果不再改变新会话。保持必要封装，不预建通用多引擎后端。

基础播放包含常用素材硬解、暂停/继续、拖动、续播、手动选集、音轨切换、内外字幕及全屏。具体编码、容器和字幕覆盖根据实测列出；硬解不承诺所有素材与设备。外部字幕仅涵盖实际可用路径，字幕在线搜索/下载系统不在首版。

观看进度通过对应 NAS 接口上报，位置归属于正确 Account、Collection 和 Episode。客户端发出请求不足以证明保存成功；再次获取 NAS 状态并重新打开续播，才证明持久化与恢复。

### 扩展预留

预留 MetadataProvider 的输入、输出与调用责任。ScrapeRequest 默认包含基名、用户输入编号或标题及语言，不传 NAS token、完整路径或播放链接。MetadataCandidate/详情携带提供者身份、来源 ID、共有元数据及有命名空间的可选扩展字段。

数据可序列化、契约版本独立于应用版本，调用支持取消和可区分的失败。提供者返回候选，核心负责用户确认、合并与保存；插件不能直接修改片库。JAV 专有字段保留为可选扩展。未来写回 NAS 单独设计。

首版只保留契约说明和实现所需最小边界；没有实际调用需求时不增加占位运行时代码。DLL ABI、脚本、Wasm、进程协议、插件加载、市场和权限运行时均不在此选型。

### 平台、资源与分发

Windows 先交付；平台代码集中处理，macOS 后续单独构建和运行验收。不能将 Windows 的播放器或 GUI 成功推断为 macOS 已支持。

采用按需片库/海报加载和有限缓存，过期任务可取消；依赖按实际功能裁剪。分别记录开发工具链/构建缓存、安装占用、片库空闲/滚动内存和播放资源；当前没有确定的数字预算，不虚构性能承诺或合格阈值。

先个人自用，记录依赖版本、二进制构建来源及许可条件；公开分发之前再决定开源/闭源、签名和更新。凭证使用系统安全存储，日志和可分享证据脱敏，用户在本机自行输入密码和验证码。

## Testing Decisions

### 主要验收边界（用户已确认）

以 Windows 实际应用的“局域网登录 → 分类/片库 → Collection 详情/Episode → 播放 → NAS 进度保存 → 再次打开续播”为主要验收路径。只验证外部行为、持久化结果和独立协议契约，不冻结内部函数、组件树或调用次数。

当前仓库仅有文档和参考资料，没有应用、测试框架、Cargo 配置或 CI。没有可复用测试先例；既有官方客户端运行证据仅作为协议线索，不作为替代实现通过证据。不预设尚未存在的构建命令或新增测试专用生产接口。

### 风险与主要证明

| 风险/要求 | 主证明与预期结果 | 能排除的可信错误 |
|---|---|---|
| 独立鉴权和片库访问 | 官方客户端与本地代理不运行时，新应用完成所需登录及真实 LAN 片库访问；失败/MFA 过期/Session 失效时显示对应恢复入口 | 复用旧 token 或代理掩盖独立链路缺失；登录失败却显示片库成功 |
| NAS 协议与流获取 | 在真实 NAS 边界记录脱敏请求方法、编码、状态和必要返回结构，使用返回流成功打开；固定样本仅证明解析契约 | 错误编码或凭证位置、静态候选当成已支持接口、过期流地址被写死 |
| 原生画面和基础控制 | 在 Windows Slint 真窗口执行暂停/继续、拖动、手动选集、音轨、内外字幕、全屏；状态和声画匹配当前 Episode | 单独播放器可用但嵌入黑屏、控制层遮挡/不可操作、旧会话回调污染新会话 |
| 实际硬解 | 对支持设备上的代表性常用素材记录编码/容器、引擎版本及实际解码路径 | 仅设置硬解选项而实际上仍软解 |
| 进度保存与续播 | 在真实 Playback session 中产生位置，核对 NAS 返回的保存结果；关闭并再次打开应用读取同一 Episode 的进度并续播，按协议精度解释偏差 | 只打印上报日志、仅保存进程内状态、写入其他 Episode |
| GUI 与资源约束 | 在海报加载、NAS 断开/请求失败及播放操作期间实际操作窗口；依据实现的缓存上限填充并确认回收、磁盘用量不持续无界增长，记录资源实测值 | UI 阻塞、退出/换页后旧请求覆盖当前页面、海报缓存无限增长 |
| 凭证保护 | 检查应用正常/失败路径产生的持久文件和可分享诊断，确认凭证在安全存储且日志无明文秘密或私密流地址 | 登录成功但敏感字段进入普通配置、日志或测试样本 |

真实链路证明不在每个内部模块重复。协议序列化/解析和视频渲染是不同失败边界，只有主路径不能定位或覆盖时补定向证明；模拟依赖不能制造“已播放”或“NAS 已保存”的成功回执。字幕不存在、只有单音轨、片库为空等状态通过适用素材验证正常呈现，不强求来源不存在的能力。

实施时使用已知内容与已知音字幕的合法、非敏感样本，列出每个素材的预期轨道及目标行为。已验证且版本、输入和环境未改变的证据复用。网络/环境阻塞与产品失败分别记录，未运行项保持未验证。插件首版按数据及调用边界审阅，不建立假运行时来测试未来能力。

完成要求：上述范围内的真实行为有证据，当前无已知阻塞；没有以未验证的代理、播放或保存行为替代通过结果。macOS、远程和高级影音不参与首版通过判断。

## Out of Scope

首版不包含远程穿透、云端中转保障、多 NAS 通用框架、独立媒体扫描/索引/刮削系统、离线片库、NAS 配套服务、HTTP 守护后台、Web 前端、可执行插件运行时和插件市场。

不承诺 macOS 已可运行、HDR、杜比视界、音频直通、所有编码/容器/字幕格式或所有硬件均可硬解。不要求多播放引擎、独立播放器进程、自动连播、字幕在线搜索下载、第三方影视服务或自动更新。

回收站列表与写操作、删除文件、清空、还原、自动修改 NAS 元数据及其他 NAS 管理模块不属于首版。实际执行删除/清空/还原需单独授权；正常播放流程中的观看进度上报属于已明确的业务写入。

公开发布、商业化、应用商店、签名和最终开源许可证选择后置；不要求用户安装插件相关运行时。

## Further Notes

已确认：Slint＋Rust；局域网首版；沿用 NAS 片库；基础播放；Windows 优先；先个人自用；插件只预留边界。验收边界已在本轮由用户确认。

尚未技术证明：Rust 独立登录及媒体流获取、MFA/Session 细节、流地址有效期、Slint 与引擎集成、硬解和音字幕覆盖。libmpv 仍是候选。开发从独立连接与原生播放前提入手，这些是实现调查工作，不是要求用户再次选择产品范围。

官方 Windows 客户端曾通过本地代理进入极影视、启动 UZPlayer/VLC 并上报递增播放秒数；此事实不证明新客户端能脱离官方运行时工作，也不证明上报已持久化。原始日志可能含敏感字段，未迁入项目；逆向报告和 catalog 是特定版本的证据，不作为跨固件通用规范。

本 spec 汇总已有 ADR、架构、扩展契约和交接资料。后续改变已确认范围时同步维护相关文档；实现细节可由开发者据证据决定，不借选型扩充首版功能。
